Major Critical Point Synthesis 使用說明

MCP 是行前規劃的「主要關鍵點」合成層：把大量 CP、命名點、地形風險、來源摘要與 OCR 標籤整理成少數人類可讀的行程錨點。它幫助 briefing、timeline、群體會合與 review，但不取代安全 CP 打卡點。

用途 不是 CP 替代品 挑選規則 UI 操作 CLI Artifact Schema 審查建議

這個功能在做什麼

MCP 會在行前規劃階段，把大量 Checkpoint Candidate、Named Point、公開來源摘要、OCR 地圖標籤、地形/風險線索與 Scout 既有 CP support，壓縮成少數「行程錨點」。

這個壓縮不是丟棄安全細節，而是把「系統需要的細節」和「人需要記住的路線主結構」分層。

MCP 不是取代安全 CP 打卡點

CP 是系統細節

Dense CP 用於細緻路線檢查、導航、風險 review、Phase 1 checkpoint 到達判斷與 runtime planning handoff。CP 可以很多，因為它服務的是系統與 reviewer。

MCP 是人類錨點

MCP 用於行前 briefing、timeline anchors、群體會合點、補水點、重大地形或決策點。MCP 要少，因為它服務的是領隊與一般隊員的共同語言。

這些 MCP 可用於集合、補水、拍照休息、風險提醒、radio check 或 post-analysis timeline 對齊；但它們不會自動改寫 safety CP check-in，也不會自動編譯 Final MissionGraph。

MCP 如何被挑出來

目前 MCP 預設 class 包含：岔路、營地/山屋/人造物、取水點、極高危險地形、隱蔽樹林/易迷路區、大景/登山口/啞口、橋樑/隧道/繩索/固定設施、行動網路通訊點。

Policy預設值意義
min_spacing_m1000MCP 之間預設至少間隔 1000m；太近時選 primary，其餘保留為 linked/suppressed。
scout_cp_support_radius_m250MCP 附近 250m 內應有 Scout CP support。
np_min_mention_ratio0.05命名點至少出現在 5% accepted evidence pages。
np_min_accepted_evidence_pages11accepted evidence page count 需大於 10。
Mandatory source familiesPTT Hiking、健行筆記、上河文化必須嘗試；缺口會記錄，且 confidence 不可升到 high。

Scoring 是 deterministic，不由模型直接決定真相。分項包含 type_weight、named_point_support、source_family_diversity、scout_cp_support、terrain_risk_support、stale_source_penalty、coordinate_uncertainty_penalty。

UI 上怎麼操作

啟動 admin server

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ./venv/bin/python -m uvicorn \
  admin_api:create_admin_app --factory --host 127.0.0.1 --port 9099

打開 http://127.0.0.1:9099/admin/pretrip。

查看 MCP layer

  1. 在地圖工具列打開 Layers。
  2. 確認 MCP checkbox 已勾選。
  3. 在左側 evidence tree 打開 Major Critical Points。
  4. 點選 MCP 查看 detail JSON；雙擊項目會讓地圖 focus 到該 MCP。

每個 MCP 摘要會顯示 confidence、CP support、route distance、mention ratio、accepted evidence pages、source families 與 suppressed count。

寫入 workspace-only review action

切到 Review tab，打開 Workspace actions，先選一個 MCP，再使用：

ButtonDecision用途
MCP acceptaccepted接受此 MCP 作為 planning anchor。
MCP linklinked連結到既有 CP candidate；UI 會提示輸入 CP id。
MCP splitsplit將過度合併的 MCP 拆成多個 target ids。
MCP downdowngraded降級並記錄原因，例如缺 source-family 或需現地確認。
MCP rejectrejected拒絕此 MCP candidate。

Review action 只寫本機 workspace log；不寫 fixture、不改 Final MissionGraph、不改 runtime、不呼叫 /safety/*。

/admin/debug

/admin/debug 可以顯示 MCP planning projection 或 debug-projection events，用於排查資料來源與 projection 是否齊全。它仍然是 read-only debug context，不是 trip planning decision surface。

CLI 怎麼使用

以下命令都使用 fixture-backed data，不需要 live network。

產生 retrieval preview

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ./venv/bin/python -m pretrip_mcp_synthesis \
  search-preview \
  --named-point-evidence tests/fixtures/pretrip/mcp/named_point_evidence.json \
  --route-name "奇萊南華" \
  --output-dir /tmp/scout-mcp-out

輸出 /tmp/scout-mcp-out/mcp_retrieval_plan.json。

合成 MCP candidates

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ./venv/bin/python -m pretrip_mcp_synthesis \
  synthesize \
  --project-root tests/fixtures/pretrip/projects/chilai_nanhua_day1 \
  --named-point-evidence tests/fixtures/pretrip/mcp/named_point_evidence.json \
  --output-dir /tmp/scout-mcp-out \
  --min-spacing-m 1000 \
  --scout-cp-support-radius-m 250 \
  --np-min-mention-ratio 0.05 \
  --np-min-evidence-pages 11

輸出 /tmp/scout-mcp-out/mcp_candidates.json。

正規化 OCR labels

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ./venv/bin/python -m pretrip_mcp_synthesis \
  normalize-ocr \
  --named-point-evidence tests/fixtures/pretrip/mcp/named_point_evidence.json \
  --output-dir /tmp/scout-mcp-out

輸出 /tmp/scout-mcp-out/mcp_ocr_labels.json。

對照 Scout CP support

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ./venv/bin/python -m pretrip_mcp_synthesis \
  reconcile-support \
  --mcp-candidates /tmp/scout-mcp-out/mcp_candidates.json \
  --output-dir /tmp/scout-mcp-out

輸出 /tmp/scout-mcp-out/mcp_cp_support_reconciliation.json。

Artifact schema 摘要

Artifact主要內容邊界
mcp_candidates.jsonMCP count、dense CP count、policy、candidate list、mention ratio、source-family coverage、nearest CP、spacing suppression、score components。candidate_only=true、runtime_safety_truth=false、compile_allowed=false
mcp_retrieval_plan.jsonsearch/fetch/structured extraction plan、queries、fetch summaries、tool contracts、source-family attempts。fixture_backed=true、live_network_performed=false、truth_decision_allowed=false
mcp_ocr_labels.jsonOCR label text、source image hash、bbox、confidence、source ref。human_review_required=true、不嵌入完整 map image
mcp_cp_support_reconciliation.json每個 MCP 的 CP support status、nearest Scout CP、suggested insertion、spacing suppression details。沒有 support 時只能 suggested insertion / review-required
mcp_review_actions.json本機 workspace append-only review log，包含 accepted、linked、split、downgraded、rejected。不代表 Final MissionGraph compile 或 runtime handoff

管理者審查建議

  1. 先看 source_family_coverage：PTT Hiking、健行筆記、上河文化是否都有嘗試；缺 mandatory family 時 confidence 不應為 high。
  2. 再看 mention_ratio 與 accepted_evidence_page_count：是否超過 5% 與 10 頁門檻。
  3. 檢查 nearest_scout_cp：250m 內是否有 Scout CP support；沒有時只能 suggested insertion / review-required。
  4. 檢查 nearby_points_suppressed_by_spacing：1000m 內被壓制的點是否語意接近；若水源與危險地形太近但操作意義不同，應 split 或保留 linked details。
  5. 看 score_components：高分是否來自合理因素，而不是單一來源或低品質座標。
  6. 最後看 boundary：確認 candidate-only、runtime_safety_truth=false、compile_allowed=false。
一般隊員說法： MCP 不是新的安全打卡規則，而是這趟路線最值得記住的幾個錨點。若 Scout runtime 或領隊安全規則另有 CP check-in，仍以那些 CP 和人工判斷為準。
