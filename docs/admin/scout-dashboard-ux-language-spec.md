# Scout Dashboard UX 語言與資訊層級規格

版本：2026-09-22

這份規格記錄 Scout Dashboard 目前發現的文字、資訊層級與控制提示問題。規則適用於所有 Dashboard 路由，不只適用於「總覽」。

## 1. 已確認的缺失

### 1.1 文字太長，主畫面難以掃讀

- 固定標語、區塊副標與操作說明不應佔據主要結果區。
- 固定文字以 20 個 words 為上限；變數資料、路線名稱、Named CP、距離、時間、百分比與檔名不受此限。
- 結論、目前狀態與下一步必須直接可見；計算方式、來源與技術限制退到提示或次要區域。

### 1.2 小字被誤當成主要資訊

- `路線結構` 的「難點、撤退點與容錯率如何分布？」是解釋，不是主結果。
- 這類問題句、定義句、資料來源句與技術補充，改為有顏色的說明圖示。
- 圖示必須支援 hover 與 keyboard focus，提示內容仍需可被螢幕閱讀器讀取。

### 1.3 學術或工程術語沒有翻譯成使用者語言

| 原用詞 | Dashboard 顯示詞 | 需要時的提示內容 |
| --- | --- | --- |
| 證據 | 系統目前狀態 | 目前資料是否足以支援下一步操作 |
| 資料邊界 | 資料用途 | 這些資料用於檢視與規劃，不會直接送出 |
| 投影資料 | 整理後資料 | 系統依目前專案整理出的可讀資料 |
| 阻擋 | 先處理 | 完成這項處理後才能繼續 |
| 需要使用者處理 | 需要先處理 | 目前仍需要人工確認或補資料 |
| 重大／次要 | 重要程度 | 依影響範圍排序顯示 |
| Dashboard 可見 | 顯示於目前頁面 | 目前頁面可以直接看到 |
| GIS 相關 | 地圖資料 | 與地圖位置或路線幾何有關 |
| 僅供重現 | 方便重現 | 用來重現當時畫面，不代表新的判斷 |
| candidate-only | 規劃用資料 | 只用於檢視與規劃 |
| technical prototype | 技術預覽 | 可檢視，但尚非正式結果 |

### 1.4 重複的頁面造成灌水感

- `決策台`、`路線脈絡`、`證據摘要` 不應只是同一份內容重新排序。
- 若控制中心、主要結果與下一步相同，應合併成一個頁面。
- 各工作流程仍可保留自己的控制中心，但總覽只保留入口與狀態摘要。

## 2. 共用介面規則

### 2.1 每頁資訊順序

1. 目前所在工作流程
2. 最重要結果
3. 下一個主要操作
4. 系統目前狀態
5. 補充資料與來源
6. 技術細節與重現資訊

### 2.2 每頁只有一個主要操作焦點

- 主要操作固定可見，不放進反覆展開的區塊。
- 目前選取狀態必須同步更新地圖、結果與側欄。
- 低頻率資訊不得使用大卡片搶佔主要視線。

### 2.3 Hover hint 規則

- 解釋性小字改為 20–24px 的有色說明圖示。
- hover 與 keyboard focus 都顯示短提示。
- 提示最多一句，直接回答「這是什麼」或「為什麼需要它」。
- 提示不可遮住主要按鈕；手機版使用 focus 或點擊可讀取的等價控制。
- 提示必須使用頁面最上層的 fixed portal，不得被卡片、抽屜、sticky rail、地圖或任何 `overflow` 容器裁切或覆蓋。
- 提示靠近視窗邊緣時自動改在控制項上方或可見範圍內，且仍緊跟觸發控制項。
- 圖示本體必須是真實語意圖示，不得用文字首字或黑色剪影代替。

### 2.4 各頁套用範圍

以下規則需套用到所有 Dashboard 路由：

- 總覽、行程規劃、地圖、時間軸、位置資料、匯入、六軸工作流程。
- 天氣、導航、路線結構、行程許可、規劃微調、除錯、系統紀錄與診斷頁。
- 首次載入、資料完整、資料不足、空狀態、錯誤與恢復狀態。
- 共用工作流程列、右側系統狀態抽屜、地圖證據側欄與頁面標題。

### 2.5 路徑顯示與捷徑

- 所有檔案、工作區與 API 路徑，只顯示最後一段名稱；完整前綴不佔主要版面。
- 每個路徑旁提供真正的 copy icon；複製內容必須是完整原始路徑，不能複製截短後的顯示名稱。
- `/admin/...` 與完整 HTTP URL 可把最後一段名稱做成可點擊捷徑；本機檔案與 `docs/...` 路徑維持顯示名稱加複製功能。
- Query string 只保留在複製值與捷徑 URL；畫面名稱只顯示最後一段，例如 `dongqing_batongguan_historic_trail_newImport` 或 `SCOUT_OUTDOOR_AI_AGENT_STANDARD.md`。
- 複製成功提供短暫、可讀的「已複製」狀態，並保留鍵盤操作與 focus 狀態。
- 不顯示沒有對應資料或操作的泛化區塊，例如「規劃用資料／不送出」、「先處理」、「重要程度」與「方便重現畫面」；若沒有具體狀態、原因或操作，就直接刪除。

### 2.6 專案名稱顯示

- 專案名稱是可辨識的工作區身分，不能因版面狹窄而縮小字型或換行。
- 超出欄位寬度時只在視覺上顯示前段加刪節號，原始名稱與 ID 不得被修改。
- 滑鼠 hover 與鍵盤 focus 必須在名稱旁／名稱上提供完整名稱提示；提示不能依賴使用者猜測或離開目前欄位尋找。
- 這項規則套用於側欄、總覽、狀態摘要、資料來源、分析摘要與其他顯示目前專案的區域。
- `project_id` 與 `trip_id` 相同時只顯示一次；只有兩者不同時才並列顯示，避免重複佔用主要版面。

## 3. 共用詞彙與圖示語言

- 路線與地圖：藍／青色，使用 route、map、navigation 圖示。
- 時間與選取：柔和紫色，使用 clock、compass 圖示。
- 結果與需要處理：琥珀色，使用 circle-alert、gauge 圖示。
- 個人與基準：柔和綠色，使用 shield-check、circle-check 圖示。
- 來源與系統狀態：暖橘色，使用 database、file-check-2 圖示。
- 除錯與事件：暖色但不使用巨大警告區塊，使用 bug 圖示。

## 4. 逐頁驗收清單

每一頁都必須確認：

- 主標題與主要結果在第一眼可讀。
- 固定說明不超過 20 個 words。
- 解釋性小字已移到 hover/focus hint。
- 不出現未翻譯的學術詞或工程詞作為主要標題。
- 主要操作只有一個，且不需要反覆展開。
- 空資料仍顯示下一步；錯誤仍可恢復。
- 地圖與目前選取狀態同步；地圖不存在時直接說明「待路線資料」。
- Named data 保留原名，不以 CP1、CP2 或流水號取代。
- 390px 寬度沒有水平溢出、中文沒有逐字直排或截斷。
- hover 與 keyboard focus 都能取得同一段提示。

## 5. 本次實作範圍

共用右側狀態抽屜、總覽、六軸入口、工作流程標頭與全頁文字替換規則已套用所有路由。頁面專屬說明文字必須沿用同一套提示元件；逐頁驗收時不得回復原有術語、長篇副標或把解釋性小字放回主要結果區。
