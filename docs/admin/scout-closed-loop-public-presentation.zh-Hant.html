Scout 三閉環運作模型

Scout 的目標不是只做一個地圖頁面，而是成為具備路線感知的戶外同行系統： 出發前協助規劃，行程中提供可觀測的安全裝置能力，回來後把經驗整理成下一次規劃的依據。 所有 AI 與資料推論都必須停留在可追溯、可審核的邊界內。

運作模型

三個閉環把 Scout 從地圖工具推進成會累積經驗的戶外系統。

目前的產品結構可以分成三條閉環。Alpha 至少必須交付第一與第二閉環； 第三閉環可以在正式 release 前完成，作為官方 workspace 轉移與生態系資料的基礎。

Alpha 必備 1. 攀爬經驗累積閉環

從 pre-trip reviewed plan、completed trip、Capability Timeline 到 Energy Reserve，再回到下一次 pre-trip 建議；這個閉環不觸發 live safety 或硬體作動。

Alpha 核心 2. On-Trip Scout Safe Device

行程中的真實節點打卡、硬體感知、空間印記播放、本地提醒、通訊行動與搜尋黑盒證據。

Release 前完成 3. Workspace 轉移與生態系

Scout A 到 Scout B 的官方 workspace template 匯出/匯入，以及 opt-in 的聚合生態系資訊。

Alpha 邊界

Alpha 不能只證明 pre-trip；它必須證明 on-trip foundation。

第一閉環證明 Scout 能從完成的行程學習。第二閉環證明使用者仍在路上時， Scout 是一個有計畫節點、有硬體狀態、有行動紀錄、有提醒能力的安全裝置。

閉環 Alpha 期待 必須守住的邊界
攀爬經驗累積 能看到 reviewed plan、completed trip record、admin post-analysis、Energy Reserve / Energy Limit feedback、下一次 pre-trip candidates。 只屬於事前準備與事後分析：不呼叫 live /safety/*、不做硬體作動、不進行真實打卡/送出，也不把 replay record 重新執行。
On-Trip Scout Safe Device 能處理 reviewed plan nodes、真實硬體/軟體狀態、Ln action traces、實體打卡、本地 cues、通訊/團隊狀態、INS/PDR 路線產生與 search black-box refs。 這是真實行動閉環，但行動仍需 runtime handoff、Ln policy、operator confirmation 與 provider policy gate。
Workspace 轉移與生態系 可等到正式 release 前；除非 alpha 測試明確需要 Scout A 到 Scout B template transfer。 匯入 template 只是候選證據，不會變成另一位使用者的 runtime truth 或 capability profile。

第一閉環：出發前

Pre-trip 把分散的路線資料整理成可審核的計畫。

來源資料GPX、DEM/DTM、影像、OSM/Overpass、route notes、文章
候選證據CP、MCP、POI、hazards、terrain、risk、route notes
Pydantic AI 輔助分群、解釋、標示衝突、呼叫 deterministic tools
人工審核接受、拒絕、拆分、降級，或要求更多證據
Reviewed package路線、CP、政策、圖層、metadata、handoff refs
MCP 壓縮大量 CP。

Major Critical Point 是給人看的主線節點，讓長距離路線不需要一點一點看完所有 candidate。

Terrain 與 risk 分開。

Hillshade、坡度、等高線與高度分層是地形 evidence；risk heat 是路線相關的 candidate risk。

AI 是整理者，不是裁判。

Pydantic AI 可以整理與解釋證據，但只有 reviewed artifact 才能往下一階段前進。

第二閉環：行程中

Scout 在路上是一個 safe device loop，不只是錄軌器。

Reviewed plan 在現場會變成可執行、可觀測的結構：Scout 追蹤計畫節點， 記錄硬體與軟體狀態，執行被允許的實體/裝置行動，說明為什麼做出提醒或紀錄，並保留必要的 black-box evidence。

Reviewed plan nodesCP、MCP、休息、危險、通訊、團隊照看
硬體感知GNSS、IMU、PDR、電池、radio、wearable、儲存狀態
真實行動打卡、cue、空間印記播放、INS/PDR route update
通訊 gateoperator-approved status、SOS、incident report、provider send
黑盒證據最小事件包、last known node、trace、device status
打卡

節點抵達、離開、missed timing 與 segment capsule state。

團隊照看

集合提示、落後成員檢查、休息需求與 buddy-check 紀錄。

通訊

訊號點、relay opportunity、queued messages 與 provider gate。

搜尋證據

保留之後可取回的 local evidence refs，預設不公開 raw private payload。

第一閉環：回程後

Post-analysis 把完成的行程轉成下一次規劃訊號。

Capability Timeline 只能從 completed user track 或 Scout runtime record 產生， 不能拿公開 reference GPX 當作使用者能力證據。它會整理分段節奏、移動/休息/總時間與信心限制。

  • Completed trip workspace 是個人能力證據的來源。
  • Energy Reserve 描述相對於個人基線的體能餘裕。
  • Energy Limit 把餘裕轉成下一次規劃的保守限制。
  • 下一次 pre-trip 可以得到休息、打卡、ETA buffer、turnaround gate 等候選建議。
僅作證據 不是醫療產品，也不是自動核准。

Energy 輸出可以輔助規劃與現場 advisory cue，但不能診斷、排名或變成 runtime safety truth。

第三閉環：release 前

Workspace 轉移讓 Scout 知識可以流動，但不複製信任。

Scout workspace template 會比公開 GPX 更豐富：它可以包含 Scout 時間、route notes、 reviewed CP/MCP、risk/terrain refs 與 redaction policy。匯入到另一台 Scout 後， 它仍然只是 pre-trip candidate evidence。

安全與信任邊界

核心規則：證據可以輔助，審核可以提升，runtime 必須明確。

Evidence 預設都是 candidate-only

Pre-trip CP、MCP、terrain、risk、route-note、AI output 與 template imports 都必須保留 provenance。

Review 人工與 AI 輔助審核

審核可以接受、拒絕、拆分、降級或要求更多 context；AI 只協助整理工作。

Runtime 不可靜默改寫

Departure、runtime handoff、outbound send、incident report 都必須明確、可稽核並受 policy gate 控制。

已規格化的開發成果

三個閉環建立在這段時間已拆開的規格基礎上。

規劃智慧

Pre-trip admin、historical GPX importer、route-corridor preparation、Overpass/OSM、MCP synthesis、terrain visualization、risk layers。

行程中可觀測性

Runtime readiness/debug tooling、admin GIS map operations、device stream admission、hardware status、on-trip debug projection。

行後學習

Capability Timeline、Energy Reserve / Energy Limit、Companion Match、reviewed lessons、future pre-trip suggestions。

結語

Scout 的公開承諾，是一個可稽核的戶外 operating loop。

Scout 應該讓使用者出發前準備得更好、在路上更容易被自己與團隊照看、回來後能把經驗留給下一次。 Alpha 應先證明規劃與 on-trip 兩條閉環；正式 release 前再補上官方 workspace transfer， 讓路線知識能在生態系中累積，同時不複製私密資料或未審核的信任。

公開簡報草案。本文件刻意不包含 raw route payload、private health samples、incident contents、 device credentials 或 live safety activation details。
