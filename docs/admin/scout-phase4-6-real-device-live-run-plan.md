# Scout Phase 4.6 Real Device Live Run Plan

Date: 2026-05-21

Status: `plan_ready_not_executed`

Target:

- runtime URL: `http://scout.local:9099`;
- expected runtime profile: `pi-field-live`;
- evidence root: `/data/scout/deployments`.

中文註釋：這份 plan 是下一次真 Apple Watch / mobile live run 的操作計畫。
它不是 live run 證據，也不是 operator approval。沒有 operator 明確批准時，
不得執行 `--send`、`--operator-approve-live-send`、`--execute` 或
`--operator-approve-control-drill`。

## Objective

Run a bounded real-device stream check against the live Scout runtime while
preserving the Phase 4.5 / Phase 4.6 safety boundary.

Success means:

- the selected Apple Watch or mobile payload batch can be signed and admitted
  through `/runtime/streams/http-push/observations`;
- telemetry deltas match the bounded send count;
- no incident package is created by the normal-route test batch;
- stream control status finishes as `observing`;
- evidence artifacts contain hashes, statuses, and counters only;
- no secret value or raw payload is copied into repo docs.

Replay-first plan:

- before true device HTTPS/portable hardware work, use
  `docs/admin/scout-phase4-6-replay-simulated-walk-plan.md`;
- generate a bounded payload batch from the prerecorded Apple Watch route;
- replay the original recorded timing at an explicit 2x or 3x multiplier;
- use that batch to simulate walking through the real-device harness.

## Non-Goals

- no automatic SOS send;
- no SMS send;
- no satellite send;
- no incident bridge opt-in;
- no live remote notification send;
- no hardware driver invocation;
- no assistant safety mutation;
- no Phase 2 Brain writeback;
- no long unattended stream soak in this first live run.

## Operator Inputs

Before execution, operator must choose:

- source kind: `apple_watch` or `mobile_phone`;
- source id, expected defaults:
  - `runtime_source.apple_watch.v0`;
  - `runtime_source.mobile_phone.v0`;
- device id for the real device;
- payload batch path on the live host;
- evidence directory timestamp.

For the first simulated walk run, the payload batch should come from:

- `runtime_stream_replay_payloads.py`;
- `tests/fixtures/routes/scout_260512_field_route.gpx`;
- `--replay-speed-multiplier 2` or `--replay-speed-multiplier 3`.

Suggested evidence directory shape:

```bash
export PHASE46_EVIDENCE_DIR="/data/scout/deployments/phase46-real-device-live-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$PHASE46_EVIDENCE_DIR"
```

## Required Secrets

Secrets stay on the live host only:

- runtime observation admission secret:
  `/data/scout/secrets/runtime-stream-admission-secret`;
- runtime stream control token:
  `/data/scout/secrets/hardware-provider-control-token` or
  `/data/scout/secrets/runtime-stream-control-token`.

The secret values must not be printed, committed, or copied into evidence
summaries.

## Step 1: Read-Only Preflight

Run read-only checks first.

```bash
curl --max-time 5 http://127.0.0.1:9099/health \
  > "$PHASE46_EVIDENCE_DIR/health.before.json"

curl --max-time 5 http://127.0.0.1:9099/runtime/streams/status-read-only \
  > "$PHASE46_EVIDENCE_DIR/runtime-stream-status-read-only.before.json"

curl --max-time 5 \
  -H "Authorization: Bearer $(cat /data/scout/secrets/hardware-provider-control-token)" \
  http://127.0.0.1:9099/runtime/streams/control/status \
  > "$PHASE46_EVIDENCE_DIR/runtime-stream-control-status.before.json"
```

Expected:

- `/health` returns `status=ok`;
- `runtime_profile=pi-field-live`;
- `runtime_stream_transport_enabled=true`;
- stream control status is `observing`;
- `token_value_exposed=false`;
- `raw_payloads_embedded=false` where reported.

Stop if:

- health is not `ok`;
- stream control status is not `observing`;
- token value appears in any response;
- raw payload appears in a status summary.

## Step 2: Real-Device Harness Dry-Run

Dry-run must happen before any send.

For the replay simulated walk, use
`$PHASE46_EVIDENCE_DIR/replay-payloads.json` generated by
`runtime_stream_replay_payloads.py`. For a later true device capture, replace it with the operator-selected real-device payload batch.

```bash
python /app/runtime_stream_real_device_harness.py \
  --base-url http://127.0.0.1:9099 \
  --payloads "$PHASE46_EVIDENCE_DIR/replay-payloads.json" \
  --secret-file /data/scout/secrets/runtime-stream-admission-secret \
  --source-id runtime_source.apple_watch.v0 \
  --source-kind apple_watch \
  --device-id "<operator-real-device-id>" \
  --evidence-dir "$PHASE46_EVIDENCE_DIR/dry-run"
```

Expected:

- `status=dry_run_ready`;
- `network_send_attempted=false`;
- `send_performed=false`;
- payload hashes and dedupe keys are present;
- raw payload and secret values are absent.

Stop if:

- dry-run is not ready;
- request body hash or payload hash is missing;
- raw payload or secret value appears in summary.

## Step 3: Bounded Live Send

Operator approval is required.

Use the same bounded replay payload path for the first simulated live-send
drill; switch to `real-device-payloads.json` only after HTTPS/device portability
preconditions are satisfied.

```bash
python /app/runtime_stream_real_device_harness.py \
  --base-url http://127.0.0.1:9099 \
  --payloads "$PHASE46_EVIDENCE_DIR/replay-payloads.json" \
  --secret-file /data/scout/secrets/runtime-stream-admission-secret \
  --source-id runtime_source.apple_watch.v0 \
  --source-kind apple_watch \
  --device-id "<operator-real-device-id>" \
  --evidence-dir "$PHASE46_EVIDENCE_DIR/live-send" \
  --send \
  --operator-approve-live-send
```

Bound the first run:

- recommended payload count: 3 to 10;
- use normal-route or non-incident-producing payloads;
- do not run unattended long stream soak in this step.

Expected:

- `status=sent`;
- `send_performed=true`;
- `response_admission_status=admitted_not_forwarded`;
- `response_transport_surface=http_push`;
- telemetry accepted delta equals sent count;
- incident file count delta is zero;
- remote provider send count is zero;
- Phase 2 writeback count is zero.

Stop if:

- any response is not accepted;
- duplicate or sequence rejection appears unexpectedly;
- safety level changes away from expected normal state;
- an incident file is created;
- remote notification or hardware control occurs;
- final status is not `observing`.

## Step 4: Optional Control Drill

This step is optional and should run only if the operator wants to test
server-side pause/resume.

Dry-run:

```bash
python /app/runtime_stream_real_device_control_drill.py \
  --base-url http://127.0.0.1:9099 \
  --operator-token-file /data/scout/secrets/hardware-provider-control-token \
  --evidence-dir "$PHASE46_EVIDENCE_DIR/control-dry-run"
```

Execution requires explicit approval:

```bash
python /app/runtime_stream_real_device_control_drill.py \
  --base-url http://127.0.0.1:9099 \
  --operator-token-file /data/scout/secrets/hardware-provider-control-token \
  --evidence-dir "$PHASE46_EVIDENCE_DIR/control-live" \
  --execute \
  --operator-approve-control-drill
```

Expected:

- pause status after is `paused`;
- resume status after is `observing`;
- final control status is `observing`;
- token value is not serialized.

中文註釋：pause/resume 是 server-side admission control，不是遙控手錶或手機停止
感測。若 final status 沒有回到 `observing`，必須停止下一步並人工修復。
