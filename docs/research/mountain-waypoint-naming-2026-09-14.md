# 山域定位點的命名慣例與 Scout CP 命名研究

查核日期：2026-09-14。狀態：研究與設計建議；尚未實作，也不構成新的 CP 取用政策。

本研究回答：山友如何指認沒有正式地名的地方，以及 Scout 如何利用這些語言替 CP 命名。以台灣山社、探勘與縱走紀錄為主，交叉閱讀登山圖書、官方地名／地形資料、國際山岳導航教學與定向越野規格。全文涉及的歷史路況只用於分析命名，未重新驗證現場狀態。

**主要發現**

台灣原作者紀錄反覆使用「高度或參照山頭＋地形／地物＋必要方位、行進事件或用途」。使用者舉出的 `H1800轉稜處`、`H1648營`、`1148鞍`，確實共同出現在 2026 年玉里山北稜紀錄。其他作者也使用數字山頭、鞍部、營地與方向關係組合；這是可交叉驗證的記錄慣例。[玉里山北稜](https://www.ptt.cc/bbs/MountainClub/M.1773371213.A.014.html)・[真。新康橫斷](https://www.nthumountain.com/article/1898)・[南澳南湖](https://www.mountain.org.tw/records/537)

官方有地名資料交換及地名管理制度；本次未找到要求所有山友自訂航點採同一種文字語法的通則。IOF 有適用於定向越野的控制點描述標準，其適用範圍也不等於所有登山活動。[內政部地名資料標準公告](https://schema.gov.tw/news/content/279)・[IOF Control Descriptions](https://orienteering.sport/iof/rules/control-descriptions/)

依這些資料提出的 Scout 建議是：讓「這個地方如何被辨認」成為名稱，把「Scout 為何選中它」保存在 CP 原因與用途。這是本研究的設計推論，並非外部規範的強制要求。

**一、實際可見的命名語法**

以下短例來自原始來源；分類名稱是本研究歸納。這些用例不能用來推算全體山友的使用率。

| 形式 | 原始短例 | 名稱所提供的線索 | 來源 |
| --- | --- | --- | --- |
| 高度＋路線轉換 | H1800轉稜處 | 在特定高度附近換稜或改變走法 | [玉里山北稜](https://www.ptt.cc/bbs/MountainClub/M.1773371213.A.014.html) |
| 高度＋地形／用途 | H1648營、1148鞍 | 未命名營地或鞍部的高度線索 | [玉里山北稜](https://www.ptt.cc/bbs/MountainClub/M.1773371213.A.014.html) |
| 參照山峰＋相對位置 | 1863峰後鞍 | 使用相鄰山頭辨認另一個地形 | [真。新康橫斷](https://www.nthumountain.com/article/1898) |
| 參照山峰＋方位＋動作 | 605峰南鞍越稜處 | 南側鞍部及越過稜線的路線事件 | [南澳南湖](https://www.mountain.org.tw/records/537) |
| 里程＋地表／功能 | 13.6K 松針營地 | 路線里程、現場地表與用途 | [南湖西稜](https://nthumountain.com/article/2041) |
| 地形交會 | 南湖溪匯流 | 水系交會，可與地圖對照 | [南湖西稜](https://nthumountain.com/article/2041) |
| 山形＋高度 | H2360假山頭 | 對未命名小山頭的行程描述 | [阿里山三霞](https://penhsuanwang.github.io/blogPage/mt-note-photo-midalt/ChaYi-alishain-mtshia-Day1/) |
| 地物＋相對位置 | 2410峰後鞍部巨石 | 在鞍部再用可見巨石縮小位置範圍 | [加里隘勇線 Day2](https://luvhiking.blogspot.com/2022/10/day2.html) |
| 既有地名／縮稱＋地形 | 木杆鞍部、主東鞍部 | 利用既有名稱及相鄰山峰關係 | [上河南湖書摘](https://www.sunriver.com.tw/takayama/nanhu.htm) |
| 路段中的相對階段 | 碎石坡頂鞍部、最後溪源 | 地形部位或沿該次行進方向的先後關係 | [上河南湖書摘](https://www.sunriver.com.tw/takayama/nanhu.htm) |

上河同一份行程同時使用里程、山屋舊址、鞍部、岔路、瀑布等不同形式；實際可辨識地物並不侷限於具有難度的路段。[上河文化](https://www.sunriver.com.tw/takayama/nanhu.htm)

原作者也可能現地取名。馬洋山紀錄明確記載在一處平台紮營後取名「鞍部營地」；這支持保留作者名稱與來源，但單篇現地取名不能視為已廣泛流通的地名。[馬洋山登山紀錄](https://ironman.idv.tw/blog/travels/2010mayangshan)

**二、其他取點原則：可辨認、可核對、可轉換路線**

Mountaineering Scotland 的導航教學選取現場可辨認的地形，包括閉合等高線、鞍部和明顯坡度轉折，也考慮路線可行性。這提供一套與「綜合壓力高」不同的選點視角：地物是否能協助核對位置。[Planning and following a route](https://www.mountaineering.scot/safety-and-skills/essential-skills/navigation/planning-and-following-a-route)

| 導航用途 | 作用 | 對 Scout 的設計啟發 |
| --- | --- | --- |
| Tick-off feature | 沿途核對已走到哪裡 | 低難度地物也可成為進度確認點 |
| Attack point | 從容易辨認的位置開始最後精確接近 | 目標前的定位基準點可獨立標示 |
| Catching feature | 遇到它代表可能已越過目標 | 與目標的先後關係比壓力分數重要 |
| Handrail | 沿線性地物保持行進方向 | 稜線、林緣等常應建模為線或路段 |

以上用途的定義來自同一份官方教學；右欄是 Scout 推論。同一地點可以在不同路線方向中有不同用途，名稱不必隨用途反覆改變。[Mountaineering Scotland](https://www.mountaineering.scot/safety-and-skills/essential-skills/navigation/planning-and-following-a-route)

IOF 2024 控制點描述將地物類型、哪一個同類地物、尺寸／交會關係、以及標旗在地物上的部位分開。原例包括 `Spur, north west foot`、`Path crossing`、`Re-entrant, upper part`。可借用的是「地物＋部位」的描述語法；IOF 本身仍有順序與控制點代碼。規格中的地物尺寸也不能誤當成海拔。[IOF 官方入口](https://orienteering.sport/iof/rules/control-descriptions/)・[2024 原文 PDF 的協會存本](https://fecamado.org/wp-content/uploads/IOF-Control-Descriptions-2024.pdf)

高度與轉向事件的結合亦有國外教學實例：Mountaintrails 以下降到 790 公尺等高線附近改變方向作說明；Chris 與 Anne Ensoll 使用一個 628 公尺標高點附近的鞍部描述路線。這支持高度作為定位線索，但沒有證據顯示 `H` 是全球統一前綴。[高度計導航教學](https://mountaintrails.ie/blog/5-top-tips-navigating-altimeter/)・[Ensoll 山岳教學](https://www.chrisensoll.com/chris-ensolls-blog/how-to-prepare-for-your-winter-mountain-leader-assessment-1-quality-mountain-days-in-scotland)

OS 等高線教學亦示範以支稜、谷地、鞍部及坡向辨認地形。據此可推論：在無地名處，高度應搭配地形和位置關係；單一高度不能唯一識別沿同一等高線的多個位置。[OS contours and relief](https://osmaps.com/discover/guides/advanced-contours-and-relief/)

**三、高度命名的四項語義區分**

1. **本點高度與參照地物高度。** 「1863峰後鞍」的數字描述參照山峰；不能直接填入鞍部海拔。原文還有不同高度的營地與取水點。[新康紀錄](https://www.nthumountain.com/article/1898)
2. **名稱中的數字與量測欄位。** `H1648營` 可以是既有山友名；新 DEM 或 GPX 量測不同，不代表應自動改寫原名。保留原名、另存高程來源，是本研究建議。
3. **等高線、標高點、GPX 高程與 DEM 推估。** 官方 FAQ 將等高線與獨立標高點分別說明；GPX 也有獨立的公尺高程欄位。僅憑名稱格式無法判斷數字來源。[內政部 FAQ，Q84](https://www.moi.gov.tw/News_toggle3.aspx?PageSize=30&_CSN=1641&n=8369&page=3&sms=9015)・[GPX 官方規格](https://www.topografix.com/gpx/1/1/)
4. **網格大小、等高距與測高精度。** 魯地圖說明使用內政部 20 m 網格 DTM；這裡的 20 m 是網格間距，不能等同等高線間隔或垂直誤差。[魯地圖製作者說明](https://rudymap.tw/)

設計示例：有原名時保留 `H1648營`；只有地形推估且尚無專名時，可以呈現「約 H1650 鞍部」。後者的取整方式仍待依來源解析度設計，並非官方標準，也不表示已證實可營宿。

**四、行話值得保存，但需要辨識它指向什麼**

多篇紀錄可見轉稜、上切、下切、腰繞、假山頭、乾溪溝、活水等詞。它們混合了地形、走法、用途和當次觀察，不能只用單一「地名」欄位抹平。[三霞紀錄](https://penhsuanwang.github.io/blogPage/mt-note-photo-midalt/ChaYi-alishain-mtshia-Day1/)・[新康紀錄](https://www.nthumountain.com/article/1898)・[加里隘勇線](https://luvhiking.blogspot.com/2022/10/day2.html)

以下是給 Scout 的處理建議：

- 地形詞保留原稱，再附標準地形類型；對不確定的行話不強行改寫。
- 上切、下切、轉稜等動作保留對應路線與方向，避免套到反向行程。
- 「活水」「乾溪溝」附觀察日期與來源。新康作者對某處水流明說穩定性不確定；歷史描述不應升格成永久狀態。
- 「營」「獵寮」須有相應紀錄或地物證據；平地或低速停留的推估只能支持候選用途。
- 人工已確認的名稱保留，系統推導名和其他山友稱呼存為別名。

清大兩篇紀錄明定一般左右按隊伍行進方向，溪流左右則按水流方向；解析名稱與描述時應保留作者的方向規約。山谷上溯紀錄也有行進右側其實是左岸的實例。[新康方向規約](https://www.nthumountain.com/article/1898)・[逆能安方向規約](https://www.nthumountain.com/article/1799)・[南澳南湖](https://www.mountain.org.tw/records/537)

`C1`、`C2` 是另一種重要差別：三霞紀錄的同一營地可在不同晚使用不同營序，逆能安也直接標示兩晚營地相同。這些應連到「本次行程中的營序」，不宜當成跨行程的唯一地名。[三霞](https://penhsuanwang.github.io/blogPage/mt-note-photo-midalt/ChaYi-alishain-mtshia-Day1/)・[逆能安](https://www.nthumountain.com/article/1799)

**五、GPX 原始註記可直接接上這套命名方式**

GPX 1.1 的航點包含 `name`、`cmt`、`desc`、`ele`，並可保留來源與延伸欄位；`note` 並非核心標準航點欄位名，應辨識來源 App 的實際輸出。完整 GPX 支援在路線點及軌跡點使用相同點型別，不能假設任何備註都必然位於獨立航點。[Topografix GPX 1.1](https://www.topografix.com/gpx/1/1/)・[原始 XSD](https://www.topografix.com/GPX/1/1/gpx.xsd)

目前 Scout 的 `pretrip_route_note_candidates.py` 已從 `wpt` 讀取 `name/cmt/desc`，分別保存原欄位，再組成 `normalized_note`，並記錄檔案 hash、航點索引與來源欄位。此研究只查核該入口，沒有實作跨所有 App 的延伸欄位適配。[本地抽取入口](/home/alexwang0315/work/scout-fusion/pretrip_route_note_candidates.py:147)・[原欄位保存](/home/alexwang0315/work/scout-fusion/pretrip_route_note_candidates.py:227)

本次沒有逐一下載七篇登山紀錄的原始 GPX，所以不能宣稱文中短例一定出現在其 GPX 的 `name` 或 `desc`。已證實的是作者文字用法，以及 Scout 現有抽取介面的資料能力。

**六、建議的 Scout 命名設計，待後續實作**

建議保留三組資訊：

| 資訊 | 回答的問題 | 示例 |
| --- | --- | --- |
| 定位名稱與別名 | 山友怎麼稱呼／辨認這個地方 | H1800轉稜處 |
| 地理描述與來源 | 這個名稱指向哪個地物、點、線或範圍 | 高度線索、稜線關係、原始航點與日期 |
| CP 用途與取用依據 | 這趟 Scout 為何要用它 | 方向確認、補給檢視、進度核對、難點 |

上述示例並未聲稱已對玉里路線完成 Scout CP 分類。官方地名模型也把名稱／別稱、位置／範圍、時間與來源分開，可作為資料結構的參考。[地名資料標準](https://schema.gov.tw/news/content/279)・[自然地理實體地名資料](https://data.nat.gov.tw/dataset/40456)

建議的名稱優先順序：

1. 使用者或審閱者確認的名稱。
2. 空間對應可靠的山友原始航點名、地名、別稱；並列來源有衝突的名稱，不以來源種類機械覆蓋。
3. 從 `cmt/desc` 抽出的地點描述，保留原文及對應關係。
4. 缺名時，才依有證據的高程、地形、地物與位置關係產生描述名。
5. 地形也無法確定時，用路線里程作定位名稱，維持未知類型，不編造營地、鞍部或危險地形。

缺名時可採以下語法，欄位依資料省略：

```text
[約] H<本點高度>＋<地形／地物>＋<必要方位或路線事件>
<參照山峰／地名>＋<相對位置>＋<地形／地物>
<路線名或里程基準>＋<里程>＋<已知特徵>
```

高度若指參照山峰，必須採第二種語法解析。無法分辨時保存原文，不猜填本點高程。里程則應保留是哪條步道／林道及其起算基準；來源的步道 K 與 Scout 從 GPX 起點計算的 K 可能不同。

同名時加方位、相鄰地物或路線里程區分；內部穩定 ID 仍可存在，顯示名稱不用承擔唯一識別。`1148鞍` 可指定位地形；包含該鞍的「稜線路」可能指整段線。來源若描述區間，不宜為了產生 CP 把整段縮成一個未經證實的位置。

這次研究也修正了先前「以難度主因命名」的優先級：難度詞適合補充原因標籤，優先使用山友能對照地圖與現場辨認的名稱。CP 的取用規則可依 Scout 定義，命名則可延續多個社群共享或各自使用的定位語言。

**七、研究方法與證據範圍**

- 深讀下表 19 組原始來源；同一規格的入口與本文算一組。三條並行子題分別處理台灣紀錄、國際導航、官方圖資；主研究查 GPX 規格、本地抽取能力與交叉核對。
- 搜尋採繁體中文及英文，不限近一年，以免排除長期記錄慣例；台灣原作者紀錄包含 2010–2026 年資料。
- 網頁搜尋用於發現，核心結論依正文。PTT 玉里紀錄全文集中在網頁解析的一行，已展開深讀；山谷與馬洋山頁面另以公開 HTTP 讀取核對關鍵段落。部分站點重讀逾時，以已成功讀取的正文或研究子題讀取結果為據。
- 僅「原始用例」「資料欄位」「教學規格」屬來源事實；命名優先級、取整、原名保留與 CP 分層是 Scout 設計推論。
- 未做全體 GPX 語料的頻率統計，不能提供各命名法普及率；未重新測量例子的高度、坐標、路況或營宿可用性。
- 沒有修改 CP、地圖或 runtime；此文件也不代表安裝永久命名策略。後續最小實驗可用使用者選定 GPX 產出「原名／推導名／解析依據」對照表，再由使用者檢視。

主要搜尋字串包括：

```text
登山紀錄 "H1800" "轉稜"
登山紀錄 "1648" "營"
登山紀錄 "1148鞍" "H1648營"

登山 紀錄 "假山頭" "乾溪溝"
登山 紀錄 "GPX" "廢工寮" "活水"
山社 紀錄 "稜肩" "匯流"
登山 記錄 "航點" "GPX" "名稱"
登山 行程記錄 "C1" "命名"
登山 "右岸" "面向下游"
登山 航點 命名 高度 鞍 營 GPS 記錄

```

國際與官方子題另外依 IOF Control Descriptions、Mountaineering Scotland route planning、spot height navigation、地名資料標準、自然地理實體資料與等高線／標高點等詞檢索，再沿官方連結閱讀原文。這是一份探索式多來源研究，並未宣稱為完整系統性文獻回顧。
