# 40 個 GIS Research Ideas：研究判讀與 Scout 可用項目

查核日期：2026-09-10。研究對象為使用者提供、署名 Mashford Mahute 的「40 GIS Research Ideas」海報。編號依原圖「由左至右逐欄、每欄由上而下」排列，每欄 10 題。

本報告是公開資料與方法的研究評估。海報提供題目，並未提供實驗或成效證據；下文的外部研究事實附來源，Scout 項目、優先順序與 V1 驗證方式則是本次工程判斷。V1 均為待執行提案，本次沒有訓練模型、下載完整 GIS 資料集、執行現地驗證或改動 Scout runtime。

## 研究結論

這 40 題對 Scout 的價值，主要來自共同使用路線、時間、地形與可追溯來源。建議將它們整合成六項能力：災害與水文證據、路線環境暴露、地表變化、生態文化脈絡、補給與交通，以及空間資料分析與學習。這樣能讓同一份證據支援行前問答、地圖、事件回放與事後分析。

最值得先證明的垂直切片是：給定一條公開 GPX 與指定時間，正確找出有效災害公告、路線相交範圍、候選溪流交會和交通出口，並讓每項結論能回到原始來源。這直接延伸 Scout 已有的地形、天氣與候選證據流程。

幾項研究界線會直接影響產品是否可信：地表溫度不等於人體熱負荷；匯流地形不等於實際水深；衛星熱異常不等於已確認火場；植生變化不等於病害或砍伐；人口網格不等於即時人流。資料解析度、時間、模型版本和實地驗證必須一起呈現，不能只增加地圖圖層。

優先順序代表與目前 Scout 的契合程度，不代表研究重要性或已取得所有 API 權限：

- **A：優先做 V1。** 可沿用現有路線與證據流程，以一個公開案例或忠實回放證明用途。
- **B：第二波。** 有實際價值，但需要新增資料、現地標註、模型驗證或情境限定。
- **C：領域延伸。** 適合未來的城市、農業、海洋或公共治理 adapter，目前 Outdoor 主線效益較低。

## 逐項研究：原圖第一欄

### 01. 氣候變遷分析

原題：GIS for Climate Change Analysis。**優先：B。**

- **研究結果：** GIS 適合比較長期溫度、降雨與極端事件的分布變化。TCCIP 已列 AR6 多尺度資料；資料目錄與 Data API 支援範圍並不完全相同。氣候情境不能用來回答某一天是否適合出發。[TCCIP 資料清單](https://tccip.ncdr.nat.gov.tw/user/ds_03_data_list.aspx)、[Data API 說明](https://tccip.ncdr.nat.gov.tw/tool_one.aspx?tool_id=20230730090021)。
- **Scout 項目：**「山區活動季節變化報告」，回答某山區不同季節的長期熱、雨環境如何改變，支援路線季節脈絡與多年資源規劃。
- **資料／方法：** 路線走廊疊合氣候格網，比較一致基期、多模式與不同 SSP 情境；保留集合分布，不只給單一均值。官方 API 文件所列 0.05 度服務需申請 token；不可假定目錄內 0.01 度資料也能用相同 API 取得。
- **V1／驗證：** 選一個山區、基期與一組未來情境，重算一項極端降雨或高溫指標，與官方圖集核對；檢查不同模式與格網尺度是否改變結論。接入 Route Context，不替代即時天氣工具。

### 02. 都市熱島製圖

原題：Urban Heat Island Mapping。**優先：B。**

- **研究結果：** Landsat 可找出地表熱區，但地表溫度不等於氣溫、體感或樹下溫度。Landsat 8 熱波段原生解析度為 100 m，30 m 交付網格不能解讀成 30 m 真實熱細節。[USGS 地表溫度產品](https://www.usgs.gov/landsat-missions/landsat-collection-2-surface-temperature)、[Landsat 8 規格](https://www.usgs.gov/landsat-missions/landsat-8)。
- **Scout 項目：**「城郊步行熱環境比較」，比較兩條路線的長期熱表面暴露，結合天氣、樹冠與休息點，支援出發時間和路線選擇。
- **資料／方法：** 經品質旗標篩選的多日地表溫度、測站氣象、樹冠／建物遮蔭與走行時間；將遙測背景與當日預報分開。
- **V1／驗證：** 兩條城市路線於數個晴天做同期量測，檢查路段熱區排序與偏差。未驗證前不輸出「改走此路可降低幾度」或個人中暑機率。

### 03. 淹水風險評估

原題：Flood Risk Assessment using GIS。**優先：A。**

- **研究結果：** 水利署淹水潛勢圖描述指定降雨及設施條件下的情境；不是下一場洪水預報，也不保證涵蓋所有山溪暴漲風險。[水利署淹水潛勢圖與使用限制](https://data.gov.tw/dataset/25766)。
- **Scout 項目：**「路線與營地淹水證據卡」，指出哪些路段位於哪一個情境的潛勢範圍，以及是否存在有效官方公告。
- **資料／方法：** 官方情境圖、路線／營地幾何、有效 CAP 警報做空間與時間相交，保留情境降雨、圖資年份、涵蓋範圍和未涵蓋區。[NCDR CAP 文件](https://alerts.ncdr.nat.gov.tw/web/developer/cap-docs)。
- **V1／驗證：** 一條公開路線，人工核對命中的路段和原圖條件；增加缺圖、過期公告、相鄰但未相交案例。證明證據取得正確，不將圖上無潛勢解讀為可通行。

### 04. 永續都市規劃

原題：GIS for Sustainable Urban Planning。**優先：C。**

- **研究結果：** 公共空間可及性需要沿路網計算；直線距離無法處理河流、圍牆和實際入口。[UN-Habitat 公共空間指標方法](https://unhabitat.org/sites/default/files/2020/07/indicator_11.7.1_training_module_public_space.pdf)。
- **Scout 項目：**「無車登山與綠地可及性」，找出大眾運輸下車後能實際走到的步道入口，以及都市綠地服務缺口。
- **資料／方法：** 公園入口、步行路網、交通站點、土地利用背景，計算路網服務範圍。NLSC WMS／WMTS 顯示服務與可下載分析向量的取得條件需分別確認。[NLSC 使用手冊](https://maps.nlsc.gov.tw/downloaddoc/UserManual.pdf)。
- **V1／驗證：** 一個行政區，以已知入口、河流和圍牆人工核對可達範圍。先證明可及性分析，再考慮都市規劃最佳化。

### 05. 空氣品質空間分析

原題：Spatial Analysis of Air Quality。**優先：A。**

- **研究結果：** 台灣公開 AQI 資料含站點、污染物和發布時間，可直接支援區域空品證據。單一測站不一定代表不同海拔或山谷的路段，更不能直接換算個人吸入劑量。[環境部 AQI 資料集](https://data.gov.tw/dataset/40448)。
- **Scout 項目：**「路線空品簡報」，在行前回答可參考哪些站、目前數值與資料缺口，並在事後回放保留當時資料。
- **資料／方法：** AQI、PM2.5 等原值、觀測時間、路線與站點距離、海拔和風場代表性；缺乏代表站時明示未知。API 需要會員金鑰。[環境部 API 說明](https://data.moenv.gov.tw/paradigm)。
- **V1／驗證：** 城市、山麓和偏遠山區各一案例；核對時間與原值，驗證缺值、過期及無代表站情況。先做來源查詢，不先假設可提供精細濃度預測。

### 06. 環境影響評估

原題：GIS in Environmental Impact Assessment。**優先：B。**

- **研究結果：** 環評書件可提供開發範圍、環境基線與審查資訊，但申請、核准、施工與完工是不同狀態；部分歷年書件也可能缺漏。[環評書件查詢](https://eiadoc.moenv.gov.tw/EIAWEB/Default.aspx)、[一般民眾操作手冊](https://eiadoc.moenv.gov.tw/files/operation_public.pdf)。
- **Scout 項目：**「路線周邊開發變動證據包」，說明沿線可能涉及道路工程、施工噪音、水域或景觀變動的公開資料。
- **資料／方法：** 文件抽取案名、範圍、日期、審查狀態與頁碼；空間相交後由 agent 說明，幾何和狀態保留原始證據，不能從計畫書推定正在施工。
- **V1／驗證：** 三份公開書件，人工核對頁碼、邊界和狀態；加入已撤案與僅規劃案例。驗證文件定位與跨文件查證能力，正式影響量化另需專業模型。

### 07. 森林火災風險製圖

原題：Forest Fire Risk Mapping。**優先：B。**

- **研究結果：** 台灣已有林火風險服務；NASA FIRMS 可補充衛星熱異常。火災氣象指數、熱點和確認火場代表不同證據，雲、林冠、濃煙與過境時差也會造成漏偵測。[林火風險評估系統](https://ffwi.forest.gov.tw/)、[NASA FIRMS 偵測限制](https://firms2.modaps.eosdis.nasa.gov/alerts/notes.php)。
- **Scout 項目：**「路線周邊林火查證包」，分別顯示背景火險、觀測熱點與官方封閉公告。
- **資料／方法：** 林火風險、FIRMS 觀測時間／信心、官方事件和路線走廊相交。台灣林火服務的機器介接方式、更新頻率與授權仍需確認。
- **V1／驗證：** 回放一件已知森林火災，核對首次通報、首次熱點、誤報與漏報。輸出需保留「未偵測到」的限制，不產生無火或可進入火場的判定。

### 08. 水文地形建模

原題：Hydrological Modeling with GIS。**優先：A。**

- **研究結果：** DEM 與 GRASS 可計算流向、匯流累積、集水區和候選河網。這些地形量不等於流量、水深或常年有水。[GRASS r.watershed](https://grass.osgeo.org/grass85/manuals/r.watershed.html)。
- **Scout 項目：**「溪流交會與上游集水區解釋」，回答路線何處穿越匯流地形、其上游集水範圍為何，以及降雨證據應查哪個區域。
- **資料／方法：** 公開 DEM、河網、路線；重用既有 MFD 候選流程，並以完整上游集水區界定運算範圍，避免只裁狹窄路線走廊而漏掉上游。[內政部 20 m DTM](https://data.gov.tw/dataset/35430)。
- **V1／驗證：** 一個公開小流域，核對河網、出口與路線交會；改變 DEM 範圍與河網閾值，報告結果敏感度。山溪洪水預報仍需降雨逕流、河道等額外模型及觀測。

### 09. 生物多樣性保育

原題：Biodiversity Conservation with GIS。**優先：B。**

- **研究結果：** 生物出現紀錄有調查努力、日期和座標誤差問題；紀錄多不必然代表多樣性高，沒有紀錄也不等於沒有物種。[TBIA 資料標準](https://docs.tbiadata.tw/biodiversity_data_standard/)、[GBIF 資料品質建議](https://techdocs.gbif.org/en/data-publishing/data-quality-recommendations)。
- **Scout 項目：**「路線生態敏感性簡報」，說明保育背景、季節觀察價值與應降低干擾的環境。
- **資料／方法：** TBIA 公開紀錄、保護區、土地覆蓋，保留採樣日期、精度與資料缺口；採用已模糊化的敏感物種資料。[TBIA 物種出現紀錄](https://tbiadata.tw/search/occurrence)。
- **V1／驗證：** 一條公開路線，人工核對物種名稱、來源、座標誤差及文字支持度；確認輸出不還原敏感位置。接入自然脈絡，不產生必定能觀察到某物種的承諾。

### 10. 災害管理

原題：GIS for Disaster Management。**優先：A。**

- **研究結果：** NCDR CAP 整合多機關示警，可支援路線有效警報查詢。平台公開瀏覽與 API／歷史下載的登入條件不同；舊警報不能當成仍生效。[NCDR 常見問題](https://alerts.ncdr.nat.gov.tw/web/platform/faq)、[CAP 文件](https://alerts.ncdr.nat.gov.tw/web/developer/cap-docs)。
- **Scout 項目：**「行程災害事件時間線」，把警報發布、更新、取消與過期，連接到路線、時間和離線證據包。
- **資料／方法：** 確定性解析 CAP identifier、references、有效時間、幾何與行政區；區分沒有警報、資料過期、服務失聯與不在服務涵蓋範圍。
- **V1／驗證：** 回放一場事件，人工核對去重、更新／取消與路線相交；加入斷線案例。這是優先證明的能力，因為其正確性可由原始公告直接驗證。

## 逐項研究：原圖第二欄

### 11. 氣候脆弱度製圖

原題：Climate Vulnerability Mapping。**優先：B。**

- **研究結果：** TCCIP 區分危害度、暴露度、脆弱度與綜合風險，並提供不同氣候情境。這類區域長期指標不能直接變成某條步道明天的危險機率。[TCCIP 風險與調適資料](https://tccip.ncdr.nat.gov.tw/a4_1.aspx)。
- **Scout 項目：**「山屋、登山口與路線氣候韌性清單」，比較哪些設施面對較高長期氣候暴露，又缺乏替代水源、出口或交通。
- **資料／方法：** 官方情境格網、設施和路網。將氣候危害、設施暴露及替代資源不足分開呈現；第 01 題描述環境怎麼變，本題描述誰受影響及調適能力。
- **V1／驗證：** 一個山區、兩個情境，重現官方區域統計，核對尺度與投影；測試權重是否讓優先巡查名單劇烈翻轉。自訂指數只能是透明的研究排序。

### 12. 野生動物棲地分析

原題：GIS in Wildlife Habitat Analysis。**優先：B。**

- **研究結果：** TBN 提供物種紀錄與 API，可支援棲地研究；潛在適生區、出現紀錄與當下現場觀測要區分。有偏差的調查資料也會使驗證結果失真。[TBN API](https://www.tbn.org.tw/data/api)、[Dubos 等：物種分布模型抽樣偏差研究](https://arxiv.org/abs/2103.07107)。
- **Scout 項目：**「低干擾路線生態脈絡」，說明路線穿越哪些潛在棲地，提供季節觀察背景和降低干擾的候選提醒。
- **資料／方法：** 公開潛在分布、土地覆蓋、保護區與有日期的紀錄；保留模型版本與敏感位置遮蔽。第 09 題重整體保育，本題重單一物種與環境關係。
- **V1／驗證：** 選三種資料較充分的物種，以獨立調查或留出地區核對。不能用同一路邊紀錄隨機分割後宣稱已驗證跨山區能力；不得由缺紀錄推論不會出現。

### 13. 三維 GIS 與都市模型

原題：3D GIS and Urban Modeling。**優先：B。**

- **研究結果：** 台灣三維國家底圖與 CityGML 等標準可支援建物、道路及城市物件的幾何與語意。三維顯示本身不能驗證熱、淹水或邊坡物理模型。[NLSC 三維國家底圖](https://www.nlsc.gov.tw/cl.aspx?n=15874)、[OGC CityGML](https://www.ogc.org/standards/citygml/)。
- **Scout 項目：**「登山口、聚落與避難據點三維演練」，在既有 DEM 路線檢視上補足建物、橋梁與入口位置。
- **資料／方法：** 合法可取得的 3D Tiles／I3S、DEM、路線與 POI；先校準水平座標、垂直基準、模型年代和遮擋。視線分析需另以確定性幾何計算。
- **V1／驗證：** 一處登山口，人工核對道路、入口、地標和高程，測試模型缺漏。價值在辨識空間關係，尚不需要建置全台數位孿生。

### 14. 土地利用／土地覆蓋變遷

原題：Land Use/Land Cover Change Detection。**優先：A。**

- **研究結果：** 地表變遷可由多期遙測辨識，但雲、山影、季節及分類流程都可能製造假變化。ESA 明示 WorldCover 2020／2021 演算法不同，直接相減會混入方法差異。[ESA WorldCover 資料限制](https://esa-worldcover.org/en/data-access)。
- **Scout 項目：**「路線環境變化候選清單」，標出新裸露地、植被減少、地表水或開發變動，供行前資料更新及巡查排序。
- **資料／方法：** 同季節 Sentinel 時序、固定處理流程與雲／山影遮罩；使用可分析數值資料，將前後影像附到候選區。土地覆蓋是物理表面，土地利用還涉及人類用途，不能完全互代。
- **V1／驗證：** 一條公開路線、兩個時段，以人工「有變／無變」樣本量測誤報和漏報。遮雲標為未知；10 m 影像不能可靠辨識所有窄步道是否仍可通行。

### 15. 土壤沖蝕製圖

原題：Soil Erosion Mapping with GIS。**優先：B。**

- **研究結果：** USLE／RUSLE 類方法處理降雨與地表逕流造成的沖蝕，不能當崩塌、土石流或瞬間斷路預測。台灣 Rm／Km 參數有適用區域及歷史資料限制。[水保署 Rm／Km 說明](https://serv.ardswc.gov.tw/E/cmm.php)、[USDA RUSLE2](https://www.nrcs.usda.gov/resources/tech-tools/water-erosion-rusle2)。
- **Scout 項目：**「步道排水與維護巡查優先區」，識別可能易受沖蝕的坡段，支援巡護工作。
- **資料／方法：** DEM 坡長／坡度、雨量侵蝕力、土壤沖蝕性、覆蓋及管理因子；報告各因子貢獻，與崩塌候選層分開。
- **V1／驗證：** 一個小集水區，用既有侵蝕溝、裸露土壤或現場巡查紀錄核對相對排序。缺乏校準時不發布精確年流失噸數，也不把排序換成通行安全等級。

### 16. 農業生產力

原題：GIS and Agricultural Productivity。**優先：C。**

- **研究結果：** 植生指標能描述生長狀態，產量模型仍需要作物、生育期、天氣與實收資料。FAO 方法特別處理生育期水分敏感性，也列出雲和作物遮罩限制。[FAO ASIS 方法](https://www.fao.org/giews/earthobservation/faq.jsp?lang=en)。
- **Scout 項目：**「Scout Agriculture 生長季異常研究助手」，作為 AIOS 的農業領域 adapter，重用時序、空間聚合和證據追溯。
- **資料／方法：** 衛星時序、[農業氣象 API](https://weather.moa.gov.tw/api/swagger/index.html) 和 [稻米產量統計](https://agrstat.moa.gov.tw/moasdweb/inquire/InquireAdvance.aspx?qcode=CC01)。區域產量只能驗證對應區域的估計，不能冒充田區實收標籤。
- **V1／驗證：** 單一作物、數個縣市，留出後續年份，比較模型與歷史平均／上一年基準的 MAE。田區預測需另有田區標註和校準，現階段與 Outdoor 主線分開。

### 17. 水資源管理

原題：GIS in Water Resource Management。**優先：A。**

- **研究結果：** 台灣河川水位可取得，但即時值可能是未經品管的原始資料。最近測站不一定在同一流域，主流水位也不證明步道旁小水源有水或可飲用。[水利署即時水位資料](https://data.gov.tw/dataset/25768)。
- **Scout 項目：**「路線水源證據卡」，整理水源歷次回報、日期、降雨及集水區背景，回答哪些資訊仍可參考、哪些已過期。
- **資料／方法：** 已授權的水源歷史回報、降雨、河系與站況；分開現地觀測、區域測站、地形推估及水質資訊。第 08 題產生地形關係，本題整合資源狀態與使用證據。
- **V1／驗證：** 一條有歷史水源紀錄的路線，核對乾濕時段、河系匹配與有水／無水回報。無近期證據顯示未知，不能自動升格成可靠補水點。

### 18. 遙測森林減損

原題：Remote Sensing for Deforestation Monitoring。**優先：B。**

- **研究結果：** UMD 森林覆蓋損失資料已更新至 2025 年，但覆蓋損失可來自火災、風災、輪伐等，不能直接推論永久森林轉用或違法砍伐。官方亦提醒跨年感測器與方法差異。[UMD GFC 2025 v1.13 與使用限制](https://storage.googleapis.com/earthenginepartners-hansen/GFC-2025-v1.13/download.html)。
- **Scout 項目：**「山區森林擾動候選檢視」，找出路線周圍值得更新資料或巡查的區域，連結前後影像及已知事件。
- **資料／方法：** 約 30 m UMD 歷史損失、同季節較新影像、官方事件及巡護紀錄；將偵測到變化與原因判斷分開。
- **V1／驗證：** 一個已知事件區，人工核對候選命中與誤判。正式面積估計需採樣與不確定性方法，不能只數像元；窄步道倒木仍須現地或更高解析度資料。

### 19. 公共衛生 GIS

原題：GIS for Public Health。**優先：B。**

- **研究結果：** 疾病統計可能依居住地、發病日或研判日歸屬，且會回補修正。區域病例不等於路線感染點或個人感染機率。[疾管署統計定義](https://nidss.cdc.gov.tw/nndss/Cdcwnh07?id=061)。
- **Scout 項目：**「行前區域公衛資訊與就醫可及性」，提供官方區域趨勢、醫療據點和路網時間，支援行前理解。
- **資料／方法：** 官方疾病彙總與公告、設施、道路；比較發生率需人口分母，並保留時間口徑和取得日。[疾管署登革熱資料](https://data.cdc.gov.tw/zh_TW/group/28a4900f-c2e5-4b81-be5d-e36ed3cea29b?groups=dengue&organization=eic&res_format=CSV)。
- **V1／驗證：** 一縣市週別趨勢，核對官方同期統計、回補和小樣本呈現；醫療可達性另外核對服務時間及道路。這是公共資訊支援，個人醫療建議需要另一套依據。

### 20. 交通路網分析

原題：Transportation Network Analysis with GIS。**優先：A。**

- **研究結果：** 成熟路由引擎已有步行與大眾運輸資料模型；最近站牌或最短路線不等於能接上當天班次。[OpenTripPlanner 資料來源](https://docs.opentripplanner.org/en/latest/Data-Sources/)、[TDX API 目錄](https://tdx.transportdata.tw/api-service/swagger/basic/2998e851-81d0-40f5-b26d-77e2f5ac4118)。
- **Scout 項目：**「登山口接駁、末班車與下撤交通」，把步行行程接到有日期的交通方案，提供候選替代出口。
- **資料／方法：** GPX 端點、步行路網、班表服務日、轉乘緩衝、道路事件。使用既有路由引擎；TDX 資料如與引擎格式不同，需明確轉換，不假設原生就是 GTFS。
- **V1／驗證：** 一個山區往返，核對平假日、跨午夜、轉乘與道路封閉；模擬錯過末班車。沒有可行方案時明確回報，不能生成不存在的班次或保證未確認步道可通行。

## 逐項研究：原圖第三欄

### 21. 再生能源場址分析

原題：Geospatial Analysis of Renewable Energy Sites。**優先：B。**

- **研究結果：** 全球太陽能與風能圖集提供區域長期資源背景，不能直接預估林下行動面板今天的充電量。地形日照模型也須補入雲、林冠與設備因素。[Global Solar Atlas](https://www.globalsolaratlas.info/support/faq)、[Global Wind Atlas](https://globalwindatlas.info/en/about/introduction)、[GRASS r.sun](https://grass.osgeo.org/grass-stable/manuals/r.sun.html)。
- **Scout 項目：**「山屋與環境感測站離網能源候選點」，比較候選位置的季節日照、地形遮蔽與設備供電情境。
- **資料／方法：** DEM、r.sun／r.horizon、植被、天氣、面板效率、儲能及負載；將資源潛勢、安裝條件和實際可用電量分開。
- **V1／驗證：** 三個公開候選點比較冬夏遮蔽及供電假設，以現地照片或已授權量測驗證遮蔽時段。只產生選址建議，不涉及自動購置或控制硬體。

### 22. 海岸帶管理

原題：GIS for Coastal Zone Management。**優先：B。**

- **研究結果：** 題目包含短期海象與長期岸線變遷。CWA 提供潮汐及波浪資料；低潮仍可能遇到長浪、暴潮或地形阻斷。岸線變遷則要處理潮位與位置誤差。[CWA 潮汐產品](https://www.cwa.gov.tw/Data/data_catalog/4-3-2.pdf)、[CWA 預報目錄](https://opendata.cwa.gov.tw/dataset/forecast?page=1)、[USGS DSAS](https://www.usgs.gov/centers/whcmsc/science/digital-shoreline-analysis-system-dsas)。
- **Scout 項目：**「海岸路線海象證據與岸線變化簡報」，擴展到海岸健行、潮間帶與濱海活動。
- **資料／方法：** GPX、預計時段、代表性預報點、潮位、浪高和官方警示；侵蝕研究另用多期岸線與 DSAS。潮位基準必須一致，不能直接與未對齊的 DEM 高程相比。
- **V1／驗證：** 三條公開海岸路線，人工核對預報點、時間、潮位基準和警示；先做海象查證。岸線變遷另選歷史案例驗證，缺資料不轉成可通行窗口。

### 23. 地下水製圖

原題：Groundwater Mapping Using GIS。**優先：C。**

- **研究結果：** 台灣地下水水位和井況可用井號串接，包含含水層與井深等重要欄位。即時原始值未必經品管，不同含水層也不能任意混合內插。[即時地下水水位](https://data.gov.tw/dataset/161082)、[觀測井井況](https://data.gov.tw/dataset/32718)。
- **Scout 項目：**「流域乾旱背景與地下水研究助手」，適合作為 AIOS 跨表、空間及時序分析案例；對山徑即時補水用途的直接性較低。
- **資料／方法：** wellidentifier、井深／含水層、站況、座標及水位時序；先做測站趨勢，再考慮同層插值。地下水位不能證明泉水可飲用或當下有水。
- **V1／驗證：** 一個井網密集區，核對井號、座標與廢站；以留站驗證比較內插和最近站基準，報告 MAE 與缺乏覆蓋的區域。

### 24. 考古遺址製圖

原題：GIS and Archaeological Site Mapping。**優先：B。**

- **研究結果：** 文資局公開資料包含指定遺址、歷史、位置與公告，適合有引用的古道脈絡；清冊不代表全部遺址。遙測中的候選地形要由考古專家確認，不能直接宣稱發現。[文資局考古遺址](https://data.gov.tw/dataset/6967)。
- **Scout 項目：**「古道與考古地景證據卡」，連接路線附近的公開指定遺址、地形與歷史背景。
- **資料／方法：** 以路線緩衝查詢公開遺址，保存 caseId、公告、來源頁與位置精度；點位不等於完整法定範圍。敏感或未公開資訊不推算、不散布。
- **V1／驗證：** 一條公開古道，逐卡核對位置、名稱、公告和敘述；登錄不等於開放參訪。新遺址偵測留作獨立專業研究。

### 25. 社會經濟不平等製圖

原題：Mapping Socio-Economic Inequality。**優先：C。**

- **研究結果：** SEGIS 提供人口、醫療、社福等統計與空間服務，可分析資源供需。年份、統計區切法及人口口徑會改變比較結果，部分服務需授權驗證。[SEGIS](https://segis.moi.gov.tw/)、[統計區資料服務](https://segisws.moi.gov.tw/STATWSSTData/StatService.asmx)。
- **Scout 項目：**「偏鄉公共服務與避難資源可達性」，讓 AIOS 比較不同區域到醫療、交通和避難設施的實際成本。
- **資料／方法：** 人口加權路網旅行時間、設施容量、服務日與地理阻隔；需要時使用考量供需的服務區模型。區域統計不能推定個人收入或脆弱性。
- **V1／驗證：** 一個山區行政區，核對人口和設施總數，測試服務半徑與區界改變的影響；輸出可解釋的缺口清單，不先建立不透明綜合排名。

### 26. 犯罪型態分析

原題：GIS in Crime Pattern Analysis。**優先：C。**

- **研究結果：** 本次查到的警政署公開資料定位多為縣市／鄉鎮市區，且屬初步統計，不足以分析特定街口或步道犯罪熱點。[警政署犯罪資料](https://data.gov.tw/dataset/14200)。
- **Scout 項目：** 至多提供「目的地行政區歷史事件背景」，或作為獨立公共統計 adapter；目前不建議加入 Outdoor 路段危險評分。
- **資料／方法：** 同案類、同期間、同粒度的統計與有分母的比較；不把行政區中心當案發位置做熱點分析，並呈現報案及定位偏差。[NIJ 熱點製圖資料品質研究](https://nij.ojp.gov/library/publications/effects-data-quality-predictive-hotspot-mapping)。
- **V1／驗證：** 重建一季區域分布，核對來源筆數、缺地點與人口口徑。不建立個人犯罪傾向分數，也不以粗粒度資料宣稱特定路段將發生犯罪。

### 27. 城市成長與蔓延

原題：Urban Growth and Sprawl Analysis with GIS。**優先：C。**

- **研究結果：** GHS-BUILT-S R2023A 多期產品提供建成面積估計，含內插與外推；10 m 產品限特定單期，不能假設所有年份均為 10 m 直接觀測。2025／2030 等推估須與歷史影像證據分開。[JRC GHS-BUILT-S](https://data.jrc.ec.europa.eu/dataset/9f06f36f-4b11-47ec-abb0-4f8b7b1d72ea)、[GHSL 版本說明](https://human-settlement.emergency.copernicus.eu/datasets.php)。
- **Scout 項目：**「郊山開發壓力長期報告」，觀察路線周邊建成面積、綠地破碎化與交通接近程度，主要服務管理和規劃。
- **資料／方法：** 一致版本的建成面積格網與歷史航照，統一投影、格網與單位；建成面積應按數值加總，不把每個非零像元都視為完全建築覆蓋。
- **V1／驗證：** 一個郊山區域的歷史估計比較，另列未來情境；用航照抽樣檢查。與第 14 題近期地表候選變化相比，本題的區域規劃用途較長期。

### 28. 再生資源監測

原題：GIS in Renewable Resource Monitoring。**優先：B。**

- **研究結果：** 森林、漁業與農業的永續需要不同指標，綠色面積增加不足以證明資源恢復。台灣第四次森林資源調查林型圖可當歷史基準，目錄更新日不等於重新調查日。[第四次森林資源調查林型圖](https://data.gov.tw/dataset/57873)。
- **Scout 項目：**「路線森林狀態與恢復觀察」，在森林擾動之外記錄後續植被恢復及林型脈絡。
- **資料／方法：** 林型歷史基準、同季節影像、巡護或樣區紀錄。NDVI 回升不等於原生林、碳庫或生物多樣性恢復；漁業與可採伐量另需領域模型。
- **V1／驗證：** 一個流域建立多年擾動／恢復候選清單，以人工樣本核對並量測雲影誤報和跨季節穩定性。第 18 題重擾動定位，本題重較長時間的資源變化。

### 29. 供應鏈管理

原題：GIS in Supply Chain Management。**優先：B。**

- **研究結果：** 可重用核心是帶容量與時間窗的路網最佳化；OR-Tools 已有 VRPTW 求解方法。LLM 可整理需求，限制檢查與求解應交由確定性程式。[OR-Tools 時間窗路由](https://developers.google.com/optimization/routing/vrptw)。
- **Scout 項目：**「多登山口接駁、補給與巡護任務規劃」，比較多車、多停靠點的安排，以及道路受阻時的替代方案。
- **資料／方法：** 道路時間矩陣、容量、停靠時間窗、任務清單、道路事件與天氣證據。山區不能以直線距離代替實際通行成本。
- **V1／驗證：** 兩台車、八個公開停靠點的離線案例，模擬一道路封閉後重算；檢查限制零違反，並與簡單貪婪法比較。求得可行解不等於已證明全域最優；不自動派遣或發送通知。

### 30. 遙測土壤含水量

原題：Remote Sensing for Soil Moisture Monitoring。**優先：B。**

- **研究結果：** SMAP SPL3SMP_E v6 描述約表層 5 cm 含水量；9 km 是發布網格，原始足跡約 36 km，插值貢獻範圍約 33 km。陡坡、密林等另有品質限制，不能當成單一路段泥濘實測。[NSIDC 使用手冊，第 2、6、10 頁](https://nsidc.org/sites/default/files/documents/user-guide/spl3smp_e-v006-userguide.pdf)。
- **Scout 項目：**「前期濕潤背景證據」，為雨後行程和流域環境提供區域背景，輔助查找需要現地回報的路段。
- **資料／方法：** 通過品質旗標的 SMAP、累積雨量、DEM 匯流、土壤和現場紀錄；區域背景與細尺度推估分開，不用重採樣製造虛假解析度。
- **V1／驗證：** 一流域回放數次降雨，與雨量基準比較；有地面含水量才評估偏差和關聯。缺地面資料時只證明取數和證據串接，不宣稱已驗證泥濘或崩塌預測。

## 逐項研究：原圖第四欄

### 31. 綠色基礎設施

原題：GIS and Green Infrastructure。**優先：B。**

- **研究結果：** 植栽、透水與滯留設施可改善局部雨水管理及熱環境，但功效依場址與設計條件而異，不能由「有綠地」直接判定防洪效能。[US EPA 綠色基礎設施環境效益](https://www.epa.gov/green-infrastructure/environmental-benefits-green-infrastructure)。
- **Scout 項目：**「城市戶外活動的綠蔭、補水與休息資源」，也可延伸成郊山入口周邊改善建議。
- **資料／方法：** 台北水綠地圖集已列公園、透水鋪面、直飲台、雨量站和滯洪設施等 GeoJSON，可與步行路網相交；實際檔案 CRS、設施狀態及可使用性仍須查核。[台北市水綠地圖集](https://data.gov.tw/dataset/166231)。
- **V1／驗證：** 一個街區串接綠地、入口、補水點與路網，現場或用近期可靠紀錄抽查可用性。改善效益模擬另需設計容量、土壤和降雨，不從設施清單直接估算效果。

### 32. 人口成長時空分析

原題：Spatio-Temporal Analysis of Population Growth。**優先：C。**

- **研究結果：** GHS-POP R2023A 將普查／行政區人口分配到格網；1975 至 2020 為估計，2025／2030 為推估。100 m 是分配粒度，不是每 100 m 的直接普查，更不是即時遊客量。[JRC GHS-POP](https://data.jrc.ec.europa.eu/dataset/2ff68a52-5b5b-4a22-8f40-c41da8332cfe)。
- **Scout 項目：**「戶外公共設施需求與城郊服務變化」，用於交通、休憩及避難資源的長期規劃。即時步道人潮需要另有入園統計或合法聚合量測。
- **資料／方法：** 一致版本人口網格、行政區統計、設施和服務範圍；分開常住人口、估計、情境推估及遊客，不混用不同定義。
- **V1／驗證：** 一個城市周邊山區，核對人口聚合是否回到來源總量、區界變更如何處理；以獨立統計檢查變化。未來推估不拿來驗證歷史模型表現。

### 33. 地理空間資料探勘

原題：Geospatial Data Mining for Predictive Analysis。**優先：A，先做探索分析。**

- **研究結果：** PySAL 等成熟工具可分析空間自相關、群聚與離群；結果依鄰接權重與尺度而變，多重檢定亦會影響熱點解讀。發現關聯尚不等於建立預測能力。[PySAL Local Moran 分析](https://pysal.org/esda/stable/user-guide/local_spatial_autocorrelation.html)。
- **Scout 項目：**「路線反覆問題與資料缺口探勘」，找出反覆慢行、偏離、回報變化或缺資料的路段，產生值得再查證的問題。
- **資料／方法：** 已授權、去識別的行程／事件回放，以路段與日期聚合，再用空間統計和時間模式分析。停留可能是休息或觀景；熱門路線事件多也可能只是使用量高，需走行次數或人時分母。
- **V1／驗證：** 用公開或合成回放建立已知群聚與無異常對照，驗證定位、分母及尺度敏感度。真實 Scout 私有軌跡另需使用授權，本次未讀取。預測留待第 40 題。

### 34. 多光譜與高光譜土地利用分析

原題：Multispectral vs Hyperspectral Imaging for Land Use。**優先：B。**

- **研究結果：** Sentinel-2 採 13 波段，空間解析度分為 10／20／60 m；EnMAP 提供較細光譜資訊、30 m 空間解析度。高光譜不等於更高空間解析度，且資料覆蓋、雲與標註仍影響成效。[Copernicus Sentinel-2](https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-2)、[EnMAP 任務規格](https://www.enmap.org/mission/)。
- **Scout 項目：**「遙測資料選型實驗」，比較對裸露地、植被、土壤或特定地景分類，增加光譜是否真的改善路線環境證據。
- **資料／方法：** 同區域、盡量同期的可用資料，共同分類標註和合理共同解析度；多光譜做可重現基準，高光譜做增益實驗。需要辨識人類土地用途時另接地籍／調查。
- **V1／驗證：** 一個有兩種影像的區域，按地區留出測試，比較各類 precision／recall、覆蓋缺口及取得成本。先確認台灣目標區實際有影像；不為比較而把低解析度資料放大當新細節。

### 35. 文化遺產保存

原題：GIS for Cultural Heritage Preservation。**優先：A。**

- **研究結果：** 文資局古蹟資料含案件、現況、公告、歷史及來源連結，足以建立有根據的文化脈絡。保存登錄、開放參觀及現地可達性是不同問題。[文資局古蹟資料](https://data.gov.tw/dataset/6246)。
- **Scout 項目：**「古道與地方文化 Route Context」，為沿途古蹟、歷史設施和聚落提供可查證背景，延伸到保存狀態與環境暴露追蹤。
- **資料／方法：** 官方清冊及公告與路線相交，保留 caseId、原文來源、日期和位置誤差。第 24 題偏遺址辨識，本題偏既有資產的脈絡與保存。
- **V1／驗證：** 一條公開文化路線，產生若干有來源的證據卡，逐條核對敘述、地點和開放狀態；資料矛盾要呈現。可直接沿用現有 Route Context，不讓模型自行補歷史故事。

### 36. 作物病害遙測

原題：Remote Sensing for Crop Disease Monitoring。**優先：C。**

- **研究結果：** 有台灣實例：農試所葉稻熱病技術以特定條件的無人機多光譜影像分析，報告 2023 年一期作於 6 處、約 2.7 公頃田區驗證，平均準確率 82%。這是該機構特定場域的報告，不能外推成通用衛星診斷準確率；公開簡介未提供完整混淆矩陣與跨年度驗證。[農試所技術簡介](https://www.tari.gov.tw/df_ufiles/b/%E9%99%84%E4%BB%B6%E4%B8%80.%E8%91%89%E7%A8%BB%E7%86%B1%E7%97%85%E8%AD%A6%E7%A4%BA%E6%8A%80%E8%A1%93%E7%B0%A1%E4%BB%8B.pdf)。
- **Scout 項目：**「Scout Agriculture 作物異常巡查助手」，先定位待檢查田區，再連接現場病害確認與處置紀錄。
- **資料／方法：** 單一作物、校正後多光譜／高光譜、天氣、生育期及真實病害標籤；缺水、缺肥與病害可能有相似訊號。讀取已授權影像不涉及自動操作無人機。
- **V1／驗證：** 一種病害，留出田區及下一期作，檢查誤報、漏報與預警提前量。沒有病害地面標籤時只能做植生異常，不能直接提供病原診斷或施藥決策。

### 37. 溢油偵測與管理

原題：GIS in Oil Spill Detection and Management。**優先：C。**

- **研究結果：** SAR 可觀察海面回波降低形成的暗斑，但低風速、洋流及生物膜也能產生相似影像；EMSA 因此將它們視為可能溢油，常需現場確認。[EMSA SAR 偵測原理與限制](https://www.emsa.europa.eu/earth-observation-products/how-does-sar-detection-work.html)。
- **Scout 項目：**「海岸污染事件證據包」，未來用於海岸活動、環境巡查或海洋領域 adapter。
- **資料／方法：** Sentinel-1 SAR、風場、可合法取得的事件及現場確認；輸出疑似區和支持／反對證據。CleanSeaNet 是方法參照，本次未驗證其服務可供台灣 Scout 直接介接。
- **V1／驗證：** 選已確認溢油和相似非溢油的公開影像案例，評估誤判與漏判。先做歷史回放，不直接判定污染物種類、責任船舶或自動通報。

### 38. 固體廢棄物管理

原題：GIS for Solid Waste Management。**優先：B。**

- **研究結果：** 台灣已有含位置、順序、表定時間與收運日的垃圾車路線資料，能直接形成有時間限制的空間查詢；表定資料不等於即時車況。[新北市垃圾車路線](https://data.gov.tw/dataset/125664)。
- **Scout 項目：**「淨山／巡護廢棄物回收安排」，或將 AIOS 延伸成社區收運查詢與任務規劃。
- **資料／方法：** 已授權的清理點、廢棄物種類、重量、容量、合法交付點與時間窗；可重用第 29 題求解器。清運點不必然接受所有活動或外地帶回廢棄物，需確認適用規則。
- **V1／驗證：** 一次模擬淨山的若干收集點，生成搬運與交付方案，核對容量、時間和交付資格；無法交付須回報。大型清運與特殊廢棄物需要另一套服務資料。

### 39. 都市植被遙測

原題：Remote Sensing for Urban Vegetation Mapping。**優先：B。**

- **研究結果：** 影像可描述植被覆蓋與變化，樹冠、樹高和街道遮蔭則需更細資料。台北河濱喬木資料提供樹高、樹冠投影、日期及座標，可作公開驗證來源，但不代表全市所有樹木。[台北河濱生態喬木](https://data.gov.tw/en/datasets/121793)。
- **Scout 項目：**「河濱與城市步行綠蔭路段」，結合第 02、31 題，讓使用者比較植被背景及特定時間的候選遮蔭區。
- **資料／方法：** 植被遙測、樹籍、建物與太陽位置；區分樹冠覆蓋、植被健康和當時道路陰影。10 m 像元不能可靠區別所有行道樹與狹窄人行道。
- **V1／驗證：** 一段河濱路線，檢查樹籍年代、樹冠定位與同期影像，再以現場照片核對遮蔭時段；季節落葉與樹木修剪列為誤差來源。

### 40. GIS 與機器學習空間預測

原題：GIS and Machine Learning for Spatial Predictions。**優先：B。**

- **研究結果：** 空間與時間相關會讓隨機分割低估預測誤差。Roberts 等以方法分析、模擬與案例說明分區驗證的重要性；分區設計也要符合要預測的新地區或新時間，避免錯估外推能力。[Roberts 等，Ecography](https://nsojournals.onlinelibrary.wiley.com/doi/full/10.1111/ecog.02881)。
- **Scout 項目：**「可校準的路段耗時或環境狀態候選模型」，先選一個有可信標籤的目標，逐步檢驗地形、天氣與歷史資料是否帶來增益。
- **資料／方法：** 路段特徵、預測當時可取得的資料、已授權且獨立的結果標籤；按整條路線、事件、隊伍和時間分組，避免同一行程相鄰點同時落入訓練及測試。
- **V1／驗證：** 先做一項目標，例如非停留時間的路段耗時；與現有規則基準比較 MAE 及區間覆蓋率，另做跨山區留出。若新模型未勝基準就記錄結果。模型預測仍是候選，不能自行改寫 Phase 1 安全狀態。

## 建議的 Scout 建設順序

以下是本次的工程優先序，不是已排程或已獲准安裝的工作。表中的原型目標是證明一條證據鏈能完成，不將研究模型當成現場決策權威。

| 順序 | 可交付項目 | 合併的主要題目 | 第一個可驗證輸出 |
| --- | --- | --- | --- |
| 1 | 路線災害與水文證據包 | 03、08、10、17、20；後續加 07、22、30 | 指定 GPX 與時間，列出有效公告、相交路段、上游集水脈絡及交通出口，逐項可回查 |
| 2 | 路線文化與自然脈絡 | 09、12、24、35 | 一條公開路線的文化／生態證據卡，含來源、日期、位置誤差與開放狀態 |
| 3 | 城郊路線環境暴露 | 02、05、31、39 | 兩條路線的空品、熱背景、綠蔭和公共資源比較，區分即時值與長期背景 |
| 4 | 地表與森林變化 | 06、14、15、18、28、34 | 一條路線的前後影像與變化候選，附誤報、漏報和未知區 |
| 5 | 交通、補給與巡護安排 | 20、21、29、38 | 一個受班表／容量／道路封閉限制的可行候選方案 |
| 6 | 空間資料探勘與預測 | 33、40 | 可重播的分析案例、獨立標籤及跨地區／時間驗證；支援前五項的資料品質改進 |

第 01、11 題可作長期氣候情境背景；第 13 題按具體三維需求增補。第 04、16、23、25、26、27、32、36、37 題則保留為 AIOS 的城市、農業、水資源與海洋領域實驗，不必全塞進 Outdoor 導航主畫面。

## 最推薦的第一個 V1

**目標問題：給定這條公開路線與這個出發時間，哪些路段有相關官方警報、匯流地形或交通阻斷證據，還缺哪些資訊？**

1. 使用一條公開 GPX 和一場有足夠歷史資料的事件；鎖定觀測時刻及資料版本。
2. 查路線識別與範圍，取得當時有效的 CAP、天氣、DEM／河網及已確認交通事件。水文分支使用完整上游範圍，其他分支可用路線走廊。
3. 確定性程式負責時區、CRS、幾何相交、警報更新／取消、數值與資料品質檢查。
4. 產生有來源的路段證據表和候選說明，agent 只根據這些結果整理理由、矛盾與缺口。
5. 人工比對原公告及已知地理關係，再重播缺資料、過期、取消、斷線等案例。

建議驗收是：已知案例的公告狀態與路段相交正確、每個結論可回查、缺證據時維持未知、重播結果一致。這能證明 Scout 的「找資料、串資料、驗資料、說明資料」能力；尚未證明洪水預測或現場安全決策準確率。

## 共用資料與執行設計

這是可實作時參考的最小 typed DAG，不要求先建一個涵蓋所有領域的大框架：

```text
路線／問題／時間
  -> 來源目錄與授權檢查
  -> 原始 artifact + hash + 觀測／發布時間
  -> schema、CRS、垂直基準、版本、品質檢查
  -> 空間相交／時間對齊／統計／確定性模型
  -> 來源充分性與矛盾檢查
  -> 路段候選證據
  -> Agent 說明 + source_refs + 未知項
```

每份證據至少要能回答：

| 必要資訊 | 原因 |
| --- | --- |
| 來源 URL、artifact hash、資料產品與版本 | 能回查與重播，避免同名產品不同版本混用 |
| observed_at、issued_at、valid_from／to、fetched_at | 取得新資料不代表觀測新；警報、情境與歷史影像的時間語意不同 |
| geometry、CRS、垂直基準、單位 | 避免經緯度、TWD97、海拔／潮位基準與單位錯配 |
| 原生解析度、發布網格、位置誤差、空間支援範圍 | 清楚區分模型格網和真實細節；SMAP 等粗尺度不可假裝是路段實測 |
| 品質旗標、缺值、有效涵蓋、模型參數與驗證限制 | 缺值不是零；未知不是低風險；各模型適用現象不同 |
| 授權、取得方式、重用與敏感性限制 | 能瀏覽、能下載、能分析與能再發布是不同條件 |
| observed／official_scenario／derived／model_candidate 類型與 review_state | 區分現地事實、官方情境和模型候選，避免自動升格 |

欄位名稱是本報告的概念建議，落地時應對齊現有 schema。保持現有來源 registry 的角色：它保存引用與審查語意，網路取得由適當資料工具負責。LLM 可以提出查詢或分析計畫，資料執行、權限、持久化與結果驗證由 runtime 負責。
