## Why This Matrix Exists

The 135 questions are not treated as simply unanswerable because they lack a live coordinate. Each row asks a stricter engineering question: if the missing evidence is provided, does Scout already have a tool that can query it, what fields must exist, and what workflow would let Scout AI answer safely?

## Tool Readiness Legend

| Status | Meaning |
| --- | --- |
| `ready_current_tool` (現有可查) | A deterministic read-only tool exists now; if the required data is present, Scout AI can query it. |
| `boundary_explain_only` (只能解釋邊界) | Scout AI can explain state/boundary, but must not mutate safety state or send outbound packets. |
| `partial_existing_surface` (部分可查，需補 resolver/adapter) | Some repo tooling or artifacts exist, but an assistant-facing resolver/adapter still needs to be connected or generalized. |
| `new_agent_tool_needed` (需要新增 agent tool) | A dedicated schema/tool/resolver is needed before this question family can be answered reliably. |

## Immediate Weather Finding

目前沒有完整的 Scout AI weather-layer parser/assessor。repo 有 admin weather overlay 與 Open-Meteo live summary path，也有 weather_daylight_evidence，但它是 candidate/reference 且 human_review_required，不能直接回答「現在是否該紮營/避雨」這類問題。

So for weather questions, simply providing a weather layer is not enough. Scout also needs `scout.ai.weather_window.assess.v0` to parse provider freshness, route-local forecast values, TTL, and route segment exposure.
